# Settings menu rework (2026-11-11)

**Status:** built (0.5.197); the system page is [menus](../architecture/menus.md#settings-screen-rebuilt-0-5-197).

## Why

The user: the current settings screen (`src/states/menu/SettingsState.lua`) is "horrible, uncomfortable, strange,
unpleasant to look at". What bothers them, in their words:

1. The player has no idea the menu scrolls (rows below the edge are invisible).
2. The background: use a checkered background for settings.
3. Every button is the same big coloured button.
4. The language changes by pressing confirm (click / Enter / Space) instead of left / right.
5. Numbers instead of sliders (volumes read "MUSIC: 10").
6. Everything is one long list instead of being grouped.
7. ON / OFF is text inside the button instead of a switch.

## What gets built

**Screen** (same logical layout rules as every menu: `docs/architecture/menus.md`, layout computed at draw time from
`WINDOW_W/H`, never at load; no stencils, clip with `src/ui/Clip.lua`):

- **Background:** a two-tone CHECKERED pattern that drifts slowly diagonally, instead of the living level background
  (`MenuScene`). It is an image file (a tile generated by a committed script in `tools/art/ui/`), tiled; the drift is
  a scroll of that tile. Colours from the game's menu palette (muted blue, like the menu buttons).
- **Title** banner "SETTINGS" at the top (`MenuList.header` style) with a clear GAP between it and the tabs (the user:
  in the current screen and in the first mockup they touch).
- **Tabs** under the title: AUDIO · CONTROLS · GAME · OTHER. The selected tab is highlighted and raised.
- **Panel:** one dark panel (the existing 9-slice panel art) holding the rows of the current tab. If a tab has more
  rows than fit, a scroll bar shows on the panel's right edge and an arrow shows that there is more below.
- **Rows:** all the same height. Option name on the LEFT, its control on the RIGHT. The selected row is highlighted
  (lighter row + gold outline, the menus' selection colour).
- **Controls:**
  - volume: a bar of 10 blocks (filled = level) plus the number (0-10);
  - on / off: a SWITCH (track + white knob; knob on the right and green track = on). The knob is **vertically centred**
    in the track (the user: in the mockup it sat low);
  - choice from a list (language, power-up wheel mode): `< VALUE >`;
  - number (rhythm sync, ms): `< VALUE >`;
  - action (credits): a button-looking row; confirm runs it.
- **Footer:** the hint line with the device's buttons (`Input.label`, as now): change, next tab, back.
- **Description:** the selected option's one-line explanation, shown in the footer panel (new translation keys
  `settings.desc_<option>`).

**Which option goes in which tab** (builder's call where not obvious, keep every current option):

| Tab | Rows |
|---|---|
| AUDIO | Music (volume) · Sound effects (volume) · Mute (switch) · Rhythm sync (ms) |
| CONTROLS | A / B swap (switch) · Vibration (switch) · Power-up wheel (`< HOLD / PRESS >`) |
| GAME | Language (`< name >`) · Hit-stop (switch) · Performance meter (switch) |
| OTHER | Credits (action) |

**Input:**

- up / down: row; left / right: change the value of the row (volume ±1, switch toggles, choice / number step);
  confirm: toggles a switch, runs an action, steps a choice forward. Language: left / right (confirm also steps).
- tabs: keyboard Tab / Q and E (or the shoulder buttons L / R on a pad) move tabs; tabs are also reachable by moving
  UP from the first row onto the tab bar and left / right there.
- mouse / touch: tap a tab; tap a row to select it; on a selected row tap its control (left half of a bar = lower,
  right half = higher, or the `<` `>`); tap a switch to toggle it.
- back: Esc / B / the corner back button, to the main menu with the gear selected.

**Main menu (`TitleState`):** the SETTINGS button leaves the button list. A **gear** button sits in the bottom-right
corner (pixel-art icon, an image from a committed generator; same corner-button family as `src/ui/CornerButtons.lua`
back button). Mouse / touch: click it. Keyboard / pad: moving DOWN from the last menu button selects the gear
(highlighted like a selected button); confirm opens settings; up goes back to the list. Its description in the footer
is the old SETTINGS one.

- The gear is drawn on every device (keyboard, pad, touch, Switch) whenever the main menu's button list is open (not on
  the "press a button" title) — it is a real button, not a pointer-only corner button (my call; the user: "todo correcto").
- The VERSION text and the hidden 7-tap debug spot (`TitleState:_versionRect`, the only way into the debug menu on
  touch devices) move from the bottom-right to the BOTTOM-LEFT corner (the user, 2026-11-11). Harnesses that tap it
  follow.
- Tab keys: new menu-only actions previous / next tab: Q and pad L = previous, E and pad R = next, Tab = next (wraps).
  They reuse keys bound to gameplay actions (`wheel`, `special`), harmless in a menu (my call; the user agreed).

## Not changing

- What is saved (`src/core/Settings.lua`, `options.cfg`), the option ids, and what each option does.
- Player-facing text stays in `assets/lang/translations.csv` (every language column); new keys for tab names and
  descriptions.

## Tests

add checks for: every option reachable, tab switching (keys, pad, touch), the scroll bar shown only when needed,
the gear reachable from the main menu by keyboard and by touch and back to it. Captures at 960 / 1280 / 1600 wide.
